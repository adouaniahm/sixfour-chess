# SixFourChess Algebraic Notation Guide

## Source of truth

This document defines the notation formats used in SixFourChess.

---

## Two formats, two usages

### 1️⃣ LAN (Long Algebraic Notation) — internal format

**Where it is used:**
- ✅ In-app move history (`ChessState.moveHistory`)
- ✅ Local game persistence
- ✅ Replay/history serialization

**Format:**
```
Start square is always included

Examples:
- e2e4     (pawn from e2 to e4)
- Ng1f3    (knight from g1 to f3)
- Bb5c4    (bishop from b5 to c4)
- e5xd6    (pawn captures on d6)
- Ng1xf3   (knight captures on f3)
- O-O      (king-side castling)
- O-O-O    (queen-side castling)
- e7e8Q    (promotion to queen)
```

**Advantages:**
- ✅ **No ambiguity**: the moving piece and source are explicit
- ✅ **Simple parsing**: no complex disambiguation needed
- ✅ **Guaranteed reconstruction**: any game can be rebuilt from history
- ✅ **Consistency**: uniform format across persistence paths

**Implementation:**
- Generated by: `AlgebraicNotationParser.toAlgebraic(move:board:)`
- Parsed by: `AlgebraicNotationParser.parseMove(_:on:)` (auto-detection)
- Source: [AlgebraicNotationParser.swift](../../SixFourChess/SixFourChess/Sources/Engine/AlgebraicNotationParser.swift)

---

### 2️⃣ SAN (Standard Algebraic Notation) — standard format

**Where it is used:**
- ✅ Historical game samples
- ✅ External PGN imports
- ✅ Interop with chess databases

**Format:**
```
Start square is included only when disambiguation is required

Examples:
- e4       (pawn to e4)
- Nf3      (knight to f3)
- Bc4      (bishop to c4)
- exd6     (pawn from e captures d6)
- Nxf3     (knight captures f3)
- Nbd7     (knight from b-file to d7)
- R1a3     (rook from rank 1 to a3)
- Qh4e1    (queen from h4 to e1)
- O-O      (king-side castling)
- O-O-O    (queen-side castling)
- e8=Q     (promotion to queen)
```

**Advantages:**
- ✅ **FIDE standard**: used globally
- ✅ **Compact**: fewer characters
- ✅ **Readable**: easier for humans
- ✅ **PGN compatible**: standard database format

**Implementation:**
- Parsed by: `AlgebraicNotationParser.parseMove(_:on:)` (auto-detection)
- Not generated by app as canonical storage format (LAN is canonical)

---

## Automatic parsing

The parser **detects format automatically**:

```swift
// Both formats are parsed:
parseMove("Ng1f3", on: board)  // LAN
parseMove("Nf3", on: board)    // SAN

// Same result:
Move(from: g1, to: f3, piece: knight)
```

**Detection logic:**
1. Check string length after piece symbol
2. If 4+ chars after symbol -> likely LAN
3. If 2 chars after symbol -> destination-only SAN
4. Use disambiguation if multiple candidates exist

---

## Format comparison

| Aspect | LAN | SAN |
|--------|-----|-----|
| **Length** | Longer (4-5 chars) | Shorter (2-4 chars) |
| **Ambiguity** | None | Possible |
| **Parsing** | Simple | More complex |
| **Generation** | Simple | Complex |
| **Standard** | No | Yes (FIDE) |
| **App usage** | Internal | Import-only |

## Code examples

### Generation (LAN only)

```swift
let board = ChessBoard()
let move = Move(from: Position(6, 4), to: Position(4, 4), ...)

// Always generates LAN
let notation = AlgebraicNotationParser.toAlgebraic(move: move, board: board)
// Result: "e2e4"
```

### Parsing (LAN or SAN)

```swift
let board = ChessBoard()

if let move1 = AlgebraicNotationParser.parseMove("Ng1f3", on: board) {
    board.makeMove(move1)
}

if let move2 = AlgebraicNotationParser.parseMove("Nf3", on: board) {
    board.makeMove(move2)
}

let moves = ["e4", "e5", "Nf3", "Nc6", ...]
let parsedMoves = AlgebraicNotationParser.parseMoves(moves, on: board)
```
